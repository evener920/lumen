# 第一章 GitHub = 免费资源库
之前给大家推荐过很多开源的软件，都是从一个叫 GitHub 的网站中发掘的。
你可以把它理解成**免费版的 App Store**。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006096/mpclipper/2026/10/03/32b6e0abc14b4ba7932c1deab8c4029f_640.png)
它现在不仅仅是程序员专门的放代码的地方，还是学习网站和各种资源网站。基本上市面上所有的资源，都能在 GitHub 上找到。可以理解为：
**1、最全的学习和资源网站**。拥有各种各样的书籍、PDF、设计文档等等。像各种的 AI 学习资料，还有供程序员学习的电子书、雅思资料等，你几乎都能找到。
**2、最强的工具和代码网站**。比如前不久 DeepSeek 的 Harness，都是开源在了 GitHub 上，还有包括之前的 MiniMax H3、ComfyUI 大模型等。
如果你想做一个 Skill，或者想做一个功能，最好的方式是先上 GitHub 搜一下，看看有没有现成的可以参考。
但大部分人以前都认为，**GitHub 只是程序员的专用网站**。
随着 AI 普及，GitHub 上越来越多的普通人，也就是非程序员，也开始往上提交代码了。包括我自己，提交的时候也会拿 GitHub 做一个存储仓库。
比如我最近在开发视频工具，就去 GitHub 上找到了一堆开源的软件，MoneyPrinter、Pixelle 等等，它们都是开源的，免费拿下来就能直接用。
今天这篇文章，就从非程序员的视角，带你从 0 开始用 GitHub。
# 第二章：开始之前：汉化和注册
**第一件：汉化**
GitHub 是国外的网站，所以界面是全英文的。不过我们可以给浏览器安装插件来解决这个问题，这里我用的是**沉浸式翻译**，你们也可以用其他的。
当然不用也可以，GitHub 来来回回只要记住那几个英文词（Star、Fork、Releases），其他都不需要管，等以后熟悉了再说。
**第二件，注册。**
打开 GitHub 官网，右上角点 Sign up。这里要输入一个邮箱，不限国内和国外。我填的是自己的 163 邮箱，再输入密码、用户名和所在国家。
恭喜你成功注册了一个账号，并且有一个免费的代码仓库了，以后你的代码可以免费托管在 GitHub 上。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006096/mpclipper/2026/10/03/d398d105eb29c2ea07a7acb351bea624_640.png)
注册完就进入个人首页，第一眼还是有点懵的，接下来我们带大家看看如何在 GitHub 上找资源。左边三条杠是菜单，中间的home显示的是Github的Copilot，这里先跳过。

这个是目前用得最多的功能，能知道当前 AI 圈的热点是什么。

# 第四章：看懂项目的详情页
首先我们来看详情页。整个页面，我们重点关注三个地方。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/4137ce151c0c8c8504beb76fc1031119_640.png)
第一，左上角项目名称区域。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006094/mpclipper/2026/10/03/62ddf97a01416768a57aa3a4c6bfb79d_640.png)
第一个名字，是作者的名称。第二个，是作者下面开源的一个项目。比如这个 Pixelle-Video，就是一个开源的视频项目，它可以一键去调度，自己去分析需求、写脚本、做分镜，把视频给产出来。
顶部的仓库导航只需关注 Issues 和 Pull Requests，它们分别代表项目目前存在的问题以及代码的修改次数。
第二，重点看下右边的 Watch、Fork、Star。
Watch
表示监控，如果项目中有任何的更新，就会以站内信或邮件的方式通知你。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/11aeddf703bf3b81e2f81eaf0749d104_640.png)
Fork
表示你可以直接复制整个项目到你自己的空间里去，方便你在这个项目的基础上进行二次开发。
可以理解为云端的复制粘贴，在你自己的账户复制了一份跟原作者一模一样的项目。
举个例子，流程是这样的：
我先把仓库用 Fork 的方式直接复制一份，它所有的历史提交、所有的更改，包括 bug 等等，都放到我们自己的仓库里去。
我再用克隆的方式，把我们自己的仓库克隆到本地。
我们在本地修改以后，再把修改以后的代码推到我们自己刚刚 Fork 下来的项目里去。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/7e46668d895463cf99112ab10d163456_640.png)
Star
可以理解为收藏和点赞，这是我们和作者都比较关心的。Star 越多，表示越受欢迎。比如今年很火的龙虾 OpenClaw，有 30 多万的 Star，可见点赞率很高。
点击 Star 后，就可以在我们的个人中心找到这个项目。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/1f3614b13b3b9bcaea3e0730deefe564_640.png)

**第三，通过项目右侧的 Release 页面。**
Release 就是当你需要下载程序的时候用的，可以理解为 download，后面我们会单独讲。
这个就是整个详情页的重点。
# 第五章：在GitHub上下载的4种方式
学会找资源后，就要知道怎么在 GitHub 中下载这些资源。GitHub 总共有四种下载方式。其实 Fork 也算，但是之前已经讲过了，所以这里主要讲这四种。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006097/mpclipper/2026/10/03/9007af9e7248c40998784ee8684fe580_640.png)
第一种，直接在 Release 页面下载安装包
这一种适合普通人，绝大多数时候都用它。
在项目的 Release 中，左边是具体的版本号，一般找最新的就行。在右边的 Assets 中找 EXE 或 DMG 结尾的文件就行。Windows 下载 EXE，Mac 下载 DMG，下载下来在本地安装就可以了，跟普通的安装软件是一样的。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/e5922dd73e43563952919b2b34e81187_640.png)
除了下载安装包，有的项目还支持一句话安装。
有的项目会在 README 里直接给你一行代码，比如 pip install xxx、brew install xxx。你把这行代码复制进电脑的终端（就是命令行窗口），回车，下载、配置、安装它全自动帮你做完，连安装包都不用去找。
第二种，下载源代码（Download ZIP）
Download ZIP 其实是下载整个项目的源代码，相当于把所有源代码都下载下来。
这个文件是没办法直接下载直接安装的。选择页面上的绿色 Code 按钮，在下拉框中选择 Download ZIP。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/fdb2a1cc3012ce53abf8d7a85de94069_640.png)
GitHub 上并不是所有的项目都有编译好或打包好的文件供你下载，有的时候还需要你自己部署环境。可以理解为它就是一个半成品，拿下来是不能用的，适合程序员去编译。
它需要安装一些环境，也就是开发环境，像 Python 或者其他类似的环境等等。
举个例子，就好比你要做一盘青菜，你手里只有原材料，你还需要盐、油、厨房，才能把它做成一盘完美的菜。
如果你真的想要安装的话，你可以把这个源代码下载下来，然后让你的 AI 去帮你处理，帮你装环境。
第三种，Clone 建立本地仓库
Clone 比源代码更进一步，它会把过往所有的提交、bug、分支历史，也就是提交的历史，全都带下来。
你可以理解为整个的开发过程，所有人做了什么事，它都完完整整地记录下来，方便你在本地开发，开发完了再提交。
有两种方式。
方式一：在电脑终端输入git clone，然后贴入你 clone 的地址
点击 Code，选择 Clone，复制 HTTPS 下面的链接地址。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/01ebc86774fa8ccd4bbcef1b7a7050b2_640.png)
打开你的电脑终端，Windows 使用 CMD 或 PowerShell，输入git clone你复制的地址。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006097/mpclipper/2026/10/03/717ffa5443ce17bc166795aef044c908_640.png)
方式二：直接让 Codex 帮你克隆，把你复制的地址丢给 Codex 就行了。
除 HTTPS 外，还有 GitHub 的 CLI 也能直接 clone。CLI 就是 GitHub 的命令行版本，主要是给 AI 使用。
所以首先要安装 GitHub CLI。直接跟 AI 说「我要安装 GitHub CLI」，安装完成后，把下图命令交给 AI 执行即可。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/3f4d6ff3f6584b35d5b8d03d75c3e7ac_640.png)
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/f8e05dd8fe9b34a9809380de6f663bfc_640.png)
最后一种是 Fork，就是云端的复制粘贴，之前已经讲过了，所以这里就略过了。
那我们总结一下：
Release 方式，直接下载成品并安装，适合绝大多数普通人使用。
ZIP 方式，适合开发者，他们可能更倾向于查看 ZIP 包内的源代码。
第三个和第四个方式，都适合想要进行二次开发的人去处理。
对于普通人来讲，后面三个大部分可以不用。
# 第六章：分支与版本
如果你未来要自己开发项目，那么分支和版本最好掌握一下，而且下面这些命令你要熟悉。但是不一定要自己写，可以让 AI 帮你代写，只要跟 AI 说「提交下本次更改的内容」或者「帮我新开个分支」等。
**先来看版本。**
GitHub 上的版本号一般是这样构成的：v2.5.23。
第一个数字是大改版，第二个是加了新功能，第三个是修了多少次小毛病。
再说 **Commit**，可以理解为保存。
每改一步，最好就存一个档，并且标注「这一步具体干了啥」。你在项目页上能看到最后一次存档是什么时候——这是判断一个项目活跃的硬指标，如果时间太久说明没人维护了。
然后是Branch，分支，你可以理解成「另存副本」。
正式版（main）不能随便动，改东西先另存一份副本，在副本上随便折腾，搞砸了删掉就行，正式版毫发无损。你只要认识两个词：main 是正式版，dev 是试验版。下载认准 main 和 Release 就对了。
最后是 PR（Pull Request）和 Merge，改完申请合并，作者点头才算数。
意思是在自己的副本上改好了，需要提交一个「申请合并」（PR），作者检查没问题，合并（Merge）进正式版。像共享文档里有人改了一段，得作者审过才抄进正稿。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006096/mpclipper/2026/10/03/1f8d57bf30ad5f2487bc52425a3bed0f_640.png)
# 第七章：License 开源协议
如果你只是下载软件自己用，绝大多数协议都随便你用，基本不用管。
如果你想拿别人的代码改改，做成自己的东西，甚至商用——那协议就是法律问题了。
GitHub 上常见的协议就两派。
宽松派：MIT、BSD、Apache。放心用，改也行，商用也行，条件就一条：保留原作者的署名声明。
严格派：GPL、LGPL、AGPL、MPL。用了它们的代码，你的代码也得跟着开源。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006096/mpclipper/2026/10/03/892112f5d85e804baa9c30a6ffa3d37f_640.png)
判断方法：看项目简介里带 GPL 的（含 LGPL、AGPL、MPL），碰了要开源；MIT、BSD、Apache，放心用，留个声明就行。
还有一个坑：仓库里压根没写协议的，默认「保留所有权利」，不能随便商用——别以为没写就是随便用。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/f3cb9d12b8a5368939bd7717def8f3e5_640.png)
# 第八章：提交你自己的项目
最后，我们提交一下自己的项目。
第一步，使用 Git 本地初始化。
就是把项目在本地先初始化。初始化好了，再准备把项目推上去。
这里的 Git 是什么意思呢？Git 是一个代码管理软件，Mac 本身自带，Windows 需要安装一下。老样子，仍然让 AI 帮我安装 Git。当然也可以自己安装，打开下图网址，找到右边的按钮，下载后直接安装也可以。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/c3ab8530eea098b4a197f946ed01b516_640.png)
它相当于一个版本管理，就跟很多在线文档的版本管理一样。你的文档要修改很多次，每一次修改 bug 或者新增一个功能，最好都要提交到 Git 保存。万一这个版本是坏的，你想从你历史保存的版本里面，选择一个先前存的版本，避免修改破坏原有的代码。
你可以理解为像游戏里面的存档一样。后面你想读取任何一个历史版本，只要 Git 一下就可以了，比较方便地去处理和保存，随便你折腾。
Git 安装完成以后，我们需要初始化我们本地的项目代码，把分支设置为 main，相当于在本地建立了一个代码仓库。
你的 GitHub 项目里面，最主要要保留这么几个信息：
第一个，源文件。
比如是个 Skill，它可能就是一个 Skill.md 文件。
第二个，说明文档，README。
说明很重要，包括项目是什么、怎么安装、项目结构、注意事项等。你可以让 AI 帮你写。
第三个，检查项目。
检查一下你的项目里面有没有遗漏的 Key、密码和各种风险。
当把这些都打包好以后，你再跟 AI 说一句：「请把我这个项目推送到我的 GitHub 里面去」。
这里注意：Git 和 GitHub 是两个工具。Git 是一个软件，GitHub 其实是一个云端的代码仓库。
这样整个第一个项目就完成了。
第二步，使用 GitHub CLI 提交代码。
最简单的方式，就是跟你的 AI 说一句：「帮我装一下 GitHub 的 CLI」。
有了它，我们就可以不用去管那些令人头疼的 Git 命令，直接让 AI 帮我们去处理提交和管理代码了。
简单来讲，就是我在本地开发完成以后，直接把这个代码上传到我的 GitHub 里去，去做合并也好，去做提交也好，就这意思。比方跟 AI 说，帮我提交下代码到我的仓库。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/0c34f03f4186896ce549d69a89678b3f_640.png)
第三步，登录 GitHub。
安装完以后，还需要你登录 GitHub。如果用的是 Codex，页面下面有个终端，打开后输入gh auth login这条命令，一路回车。也可以直接在电脑终端或命令行下输入。
中间会做登录校验，校验码就是你终端的这串数字，把它输入到网页中的授权页面。
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006096/mpclipper/2026/10/03/6ce73dc73b990e2cf9a66934dcbd1419_640.png)
第四步，提交项目到代码仓库。
跟 AI 说清楚以下几件事：提交到哪个仓库、仓库是开放的还是仅你可见、以及分支是哪个。
仓库名称：GitHub 上新建的这个仓库叫什么名字，如果不存在，AI 会自动创建一个该名字的仓库。
可见性 Public：公开，全网都能看（你第四章讲的 Public 标识）
推送分支 main：把 main 分支 —— 第六章讲的「正式版」—— 推上去
![image](https://res.cloudinary.com/dqvoyeo3x/image/upload/v1791006095/mpclipper/2026/10/03/eb6765ebf37fbf4fc5d3bef01bd37e0f_640.png)
至此，推送完成。
其实 GitHub 不仅仅可以提交代码，像图片、文档等形式的文件都可以提交。
# 写在最后
回头看这一篇整下来，我们至少完成了这些事情。

第二，看懂代码仓库或项目页面。
重点关注 Fork、Star，还有 Release 这几个。

有四种获取资源的方法，比如直接下载直接用、克隆、下载压缩包，还有云端的复制粘贴。
第四，用 GitHub CLI 创建和提交开源项目。
下次想要做什么软件，可以先去 GitHub 上搜一搜，会省去很多功夫。
